# Canopy Extractor — プロトタイプ v0.5.0

CHM (樹冠高モデル) から**樹頂点**と**単木の樹冠ポリゴン**を抽出する QGIS プラグイン。
GRASS / GDAL のアルゴリズム連鎖と中間ファイルを使わず、numpy の配列演算で完結する。

Processing プロバイダ ID は `canopyextractor`。アルゴリズムは 2 つ。

| アルゴリズム | ID | 内容 |
|---|---|---|
| 樹頂点抽出 | `canopyextractor:extracttreetops` | 局所最大値法 |
| 樹冠ポリゴン生成 | `canopyextractor:extractcrowns` | 領域拡張 / ボロノイ |

> **v0.2.0 からの移行**: プラグインのフォルダ名とプロバイダ ID が変わった。
> 古い `tree_top_extraction` フォルダは削除すること。モデルデザイナで
> `treetop:extracttreetops` を参照しているモデルは差し替えが必要。

## 1. 樹頂点抽出

元の Processing モデル `樹頂点抽出0_5_0.model3` を置き換えたもの。

| 元モデル | 本実装 |
|---|---|
| `grass:r.neighbors` (method=maximum, size=7) | 分離型最大値フィルタ |
| `gdal:rastercalculator` (`A==B`) | 配列比較 |
| `gdal:polygonize` | 廃止 (`np.nonzero` で直接セル座標) |
| `native:centroids` | 連結成分の重心 |
| `native:rastersampling` | 読み込み済み配列から直接取得 |
| `native:extractbyattribute` (`>= 6`) | `min_height` パラメータ |

### パラメータ

| 名前 | 既定値 | 説明 |
|---|---|---|
| CHM ラスタ / バンド | — | 入力 |
| 近傍窓のサイズ | 7 | 奇数。元モデルの `size=7` に対応 |
| 最低樹高 | 6.0 | 元モデルの `height_1 >= 6` に対応 |
| 平坦な樹頂部を 1 点に統合する | ON | polygonize→centroids に相当 |
| 平滑化 | なし | なし / 平均フィルタ / ガウシアン |
| 平均フィルタの窓サイズ | 3 | 奇数。lidR の例と同じ既定値 |
| ガウシアンの sigma | 0.5 m | **メートル指定**。内部でセル数に換算 |
| 樹高の取得元 | 元の CHM | 元の CHM / 平滑化後の CHM |
| 処理範囲 | (任意) | キャンバスの表示範囲や座標。指定範囲だけをタイル分割して読む |
| 処理範囲ポリゴン | (任意) | ポリゴンの内側にある樹頂点だけを残す (事後フィルタ) |
| 処理ブロックサイズ | 2048 | 詳細パラメータ |

出力フィールドは `id` / `height` / `n_cells`。

### 平滑化について

itcSegment の原著手順では、局所最大値を探す前にローパスフィルタで CHM を平滑化して
偽の極大を減らす。lidR のドキュメント例でも 3x3 平均フィルタをかけている。
北海道森林管理局 網走東部の実証業務では、カラマツで現地比 109% の過剰抽出が
報告されており、その一部は細かい凹凸に由来すると考えられる。

**NoData の扱い** — 素朴に畳み込むと NoData が周囲に滲み出す。正規化畳み込みを使う:

    有効セルを 1、NoData を 0 とした重み w を用意し、smooth(値 * w) / smooth(w)

これでラスタの端も無立木地の縁も「実際に存在するセルだけの平均」になる。

**sigma はメートル指定** — 0.4m CHM と 0.5m CHM でパラメータの意味が変わると
現場で事故のもとになるため、セルサイズから自動換算する。半径は
`scipy.ndimage.gaussian_filter` と同じ規則 (`truncate=4.0`) で決める。

**樹高は既定で元の CHM から取る** — 平滑化は樹冠の頂点をわずかに削るので、
平滑化後の CHM から樹高を取ると系統的な過小評価になる。

**タイル処理の halo** — 平滑化のカーネル半径を halo に加算している。

#### 効果の測定（合成データ）

14 セル間隔で放物面樹冠を配置し（正解 169 本）、振幅 3.0 のノイズを載せた場合:

| 近傍窓 | 平滑化なし | ガウシアン sigma=1.5 セル |
|---|---|---|
| 3 セル | 732 点 | 169 点 |
| 5 セル | 198 点 | 169 点 |
| 7 セル | 172 点 | 169 点 |

## 2. 樹冠ポリゴン生成

樹頂点ポイントと CHM から単木の樹冠を切り出す。方式は 2 つ。

### 領域拡張 (Dalponte & Coomes 2016)

種セルから 4 近傍へ条件付きで拡張する。PyCrown の Cython 実装で確認した条件:

1. `nb_h > th_tree`
2. `nb` が他の樹冠に未割当
3. `nb_h > seed_h * th_seed`
4. `nb_h > mean_h * th_cr` (`mean_h` は現在の領域平均高)
5. `nb_h <= seed_h * 1.05`
6. 種からの距離が `max_cr` 未満

条件 5 と 6 は lidR のドキュメントには書かれていないが実装には入っている。
条件 6 は原著ではチェビシェフ距離（正方形）。PyCrown は円形に改変している。
本実装は既定を円形、詳細パラメータで正方形に切替可能。

**ベクトル化** — 原著はセル単位の逐次ループ（PyCrown が Cython / Numba を
使っている理由）。本実装はフロンティア方式でベクトル化した。前回追加された
セルの 4 近傍だけを候補として一括判定し、1 反復で全樹冠を 1 セル分広げる。

原著との差異は 2 点:

- `mean_h` の更新粒度がセルごとから反復ごとになる
- 競合の解決が走査順の先着から「種に近いほう」になる

合成データで逐次参照実装と比較したところ、**ラベル一致率 99.8%、割当セル総数の
差は 0.01% 未満**。差は複数の樹冠に等距離で隣接するセルの帰属だけ。
テストコードに参照実装を残し、一致率が 99% を下回ったら失敗するようにしてある。

### ボロノイ (Silva et al. 2016)

最大半径を切った最近傍割当。種ごとに円板を焼き込み、より近い種があれば上書きする。
`exclusion` 未満の低いセルは除去する。単純で速いぶん、樹冠の形は幾何的になる。

### パラメータ

| 名前 | 既定値 | 説明 |
|---|---|---|
| CHM ラスタ / バンド | — | 入力 |
| 樹頂点 | — | 樹頂点抽出の出力 |
| 樹木 ID フィールド | (任意) | 空なら通し番号 |
| 分割方式 | **ボロノイ** | 領域拡張 / ボロノイ |
| 樹冠の最大半径 | 10.0 m | **メートル指定**。内部でセル数に換算 |
| 樹木とみなす最低高 | 2.0 m | `th_tree` |
| 種の高さに対する割合 | 0.55 | `th_seed`（領域拡張） |
| 領域平均高に対する割合 | 0.55 | `th_cr`（領域拡張） |
| 除去する高さの割合 | 0.3 | `exclusion`（ボロノイ） |
| 樹冠の広がり方 | 円形 | 円形 / 正方形（原著と同じ）。詳細 |
| 樹冠を樹頂点と連結した部分に限る | ON | ギャップの飛び越えを防ぐ |
| 立木地マスク | (任意) | 0 / NoData のセルを樹冠から除外 |
| マスクのバンド | 1 | |
| マスクの意味を反転する | OFF | 無立木地マスクを渡す場合に ON |
| 処理範囲 | (任意) | キャンバスの表示範囲や座標。指定範囲だけをタイル分割して読む |
| 処理範囲ポリゴン | (任意) | ポリゴンの外側を無立木地扱いにする (ラスタ化して立木地マスクと同じ経路で適用) |
| 樹冠内の穴を埋める | OFF | scipy 必須。詳細パラメータ |
| 処理ブロックサイズ | 2048 | 詳細 |

`th_tree` の既定 2.0 は「樹木とみなす最低高」で、樹頂点抽出の `min_height`
（既定 6.0、元モデル由来）とは別物。混同しないこと。

### 出力属性

| フィールド | 内容 |
|---|---|
| `id` | 樹木 ID（入力点から引き継ぐ） |
| `height` | 樹高（樹頂点の CHM 値） |
| `crown_area` | **樹冠投影面積 (m2)** |
| `crown_dia` | 等価円直径 `2*sqrt(area/pi)` (m) |
| `crown_max` | 樹冠内の最大高 |
| `crown_mean` | 樹冠内の平均高 |
| `n_cells` | 構成セル数 |

`crown_area` はセル数 × セル面積で直接求める（ポリゴン化後の面積計算ではなく）。
北海道森林管理局 網走東部の実証業務では、この樹冠投影面積が樹種別の
胸高直径推定式に入り、材積式で蓄積量が算出される。

### タイル処理の halo

**halo は `2 * max_cr + 1` が必要。** あるセルを奪いうる競合の種は、種から
最大 `2 * max_cr` 離れている（セルは種から `max_cr` 以内、競合はそのセルから
`max_cr` 以内）。`halo = max_cr` だと密な林分でタイル境界付近の帰属がずれる。

これは実測で確認した。10 セル間隔の密な林分・5 通りの乱数種で、
`halo = max_cr + 1` では 11〜188 セルの不一致が出るが、`halo = 2 * max_cr` では
全条件で完全一致する。テストに両方を入れてある（不足する halo で不一致が
出ることも回帰テストにしてある）。

種の並び順も結果に影響する（同距離の競合はラベル番号の小さいほうが勝つ）ため、
アルゴリズムは常に行順にソートした順序を使う。ブロックはその連続部分を切り出す
だけなので、ブロック間で一貫する。

種がコア領域内にある樹冠だけを出力するので、**ポリゴンがタイル境界で分断される
ことはない**。全域のラベルラスタをメモリに持つ必要も、一時ファイルも不要。

### ポリゴン化

主経路は `gdal.Polygonize`。MEM ドライバのラスタに `WriteRaster()` で
バイト列を渡すので、`osgeo.gdal_array` を一切経由しない（v0.1.1 で踏んだ
numpy ABI 問題は再発しない）。

フォールバックはセル境界の辺を追跡する自前実装。各セルの 4 辺のうち隣が
同じラベルでない辺だけを残し、有向辺として繋ぐ。辺の向きを統一してあるので、
符号付き面積で外環と内環（穴）を区別できる。GDAL が使えない環境向けの保険で、
Python ループなので大量の樹冠では遅い。どちらの経路を使ったかはログに出る。

### 出力スタイル

出力レイヤが QGIS に読み込まれるとき、`QgsProcessingLayerPostProcessorInterface`
で既定のスタイルを適用する。塗りは緑系の単一シンボルで、**シンボルの不透明度を
50%** にしてあるので、下に敷いた CHM やオルソ画像が透けて見える。

レイヤ全体の不透明度ではなくシンボル側に設定しているため、スタイルを
`.qml` に保存すれば他のレイヤにもそのまま流用できる。

### 処理範囲の絞り込み

「処理範囲」と「処理範囲ポリゴン」は樹頂点抽出・樹冠ポリゴン生成の両方にある。
役割が異なるので使い分ける。

**処理範囲 (`QgsProcessingParameterExtent`)** — キャンバスの表示範囲や座標を
矩形で指定する。CHM 全体を読まずに, 指定範囲だけをタイル分割して処理するため、
広域の CHM から一部だけを素早く試したいときに使う。範囲の外側は一切読み込まない。

範囲は内部で `extent_to_region()` によりピクセル範囲に変換する。セル境界に
一致しない範囲を指定した場合は, セルを切り詰めず外側に広げる (中途半端な
範囲指定で対象セルが 0 個になる事態を避けるため)。halo (近傍窓や樹冠半径の
ぶんの周辺読み込み) は処理範囲の外, ラスタ全体の範囲までなら及んでよいので、
範囲の縁で計算精度が落ちることはない。

**処理範囲ポリゴン (`QgsProcessingParameterFeatureSource`, ポリゴン)** — 小班界
など矩形でない範囲を指定したいときに使う。挙動はアルゴリズムによって違う。

- *樹頂点抽出*: 全ての候補点を求めたあと, ポリゴンの内側にある点だけを残す
  事後フィルタ。ポリゴン群はあらかじめ 1 つに合成 (`unaryUnion`) し、
  ジオメトリエンジンで判定するため、ポリゴンの数が多くても点ごとの判定は
  高速に行える。
- *樹冠ポリゴン生成*: ポリゴンの外側を無立木地マスクと同じ扱いで除外する。
  `gdal.RasterizeLayer` でブロックごとにラスタ化する (`gdal.Polygonize` と
  同じく MEM ドライバ + ReadRaster 経由なので `osgeo.gdal_array` を通らない)。
  既存の立木地マスクと同じ仕組みで `valid` 配列に反映されるため、樹冠が
  ポリゴン境界を飛び越えるのを「樹頂点と連結した部分に限る」オプションと
  合わせて防げる。

どちらのポリゴンパラメータも, CRS が CHM と異なる場合は自動的に座標変換する。

### 無立木地の除外

3 段階で効かせられる。

**1. 樹木とみなす最低高 (`th_tree`)** — この高さに満たないセルは樹冠に入らない。
裸地や草地はこれで落ちる。

**2. 樹冠を樹頂点と連結した部分に限る (既定 ON)** — ボロノイは距離だけで
割り当てるため、林道や無立木地のギャップを飛び越えて向こう側のセルを
樹冠に取り込むことがある。種から 4 連結で到達できないセルを落とすことで
これを防ぐ。領域拡張は元から連結なので冪等 (結果は変わらない)。

タイル分割との整合性も確認済み。連結性を入れても全域処理と完全に一致する
(密な林分・5 通りの乱数種で検証)。

**3. 立木地マスク (任意のラスタ)** — 立木地を 0 以外、無立木地を 0 か NoData と
したラスタを渡すと、そのセルを樹冠から除外する。「マスクの意味を反転する」を
ON にすれば、無立木地を 1 としたラスタも使える。

セルサイズが CHM と違っていても、QGIS のラスタプロバイダが最近傍で合わせて
読む。ただし CRS が違う場合は再投影されないので警告を出す。

小班界などのポリゴンを使う場合は、あらかじめ「ベクタをラスタ化 (rasterize)」で
CHM と同じ CRS のラスタにしてから渡す。

> **樹頂点抽出の 2 値化画像は使えない。** 元の Processing モデルにあった
> `A==B` の 2 値化ラスタは、局所最大となったセル (樹頂点そのもの) だけが 1 の
> 画像で、立木地・無立木地の情報は持っていない。マスクには使えない。
> なお現行の実装ではこの中間ラスタ自体を生成していない。

### 形状の扱いについての注意

網走東部の事例で樹冠ポリゴンが使われているのは**面積**であり、形状の細部ではない。
加えて、衛星画像から推論した CHM は実効解像度がグリッド間隔より粗い。

- セル境界そのままの階段状ポリゴンで実用上は十分
- **樹冠形状から樹種を判別するような下流処理には使わないこと**

## 3. ラスタ読み込みについて

GDAL の `Band.ReadAsArray()` は内部で `osgeo.gdal_array`（C 拡張）を import する。
これは numpy の ABI に結び付いてビルドされているため、GDAL と numpy のビルド
組み合わせによっては `numpy.core.multiarray failed to import` で落ちる環境がある。

本実装は `Band.ReadRaster()` で生バイト列を受け取り numpy 側で解釈するため、
`gdal_array` に一切依存しない。さらに `open_reader()` はリーダ生成後に 1 セルだけ
試し読みを行い、失敗したら QGIS のラスタプロバイダ経由（`QgsRasterBlock`）に
自動で切り替える。

QGIS 無しで実行できる（52 テスト）。

```
python -m unittest discover -s canopy_extractor/tests -t . -p 'test_*.py' -v
```

| 対象 | 検証内容 |
